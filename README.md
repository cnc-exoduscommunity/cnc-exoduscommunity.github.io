The community site for the Command & Conquer: Renegade **Exodus Co-Op** server,
built with [Jekyll](https://jekyllrb.com/) and hosted on GitHub Pages at
<https://cnc-exoduscommunity.github.io>.

### How to connect

1. <span id="irc-step-1" class="step-anchor">**Add the server.**</span> In your client's server list, add a new network with server `85.215.107.108`, port `6667`, and SSL/TLS turned **off**. In HexChat, the server is written as `85.215.107.108/6667`; leave "Use SSL" unticked.
2. <span id="irc-step-2" class="step-anchor">**Pick a nickname.**</span> Using your in-game name makes you easy to recognise.
3. <span id="irc-step-3" class="step-anchor">**Connect.**</span> If you try to join the channel now you will get *"unable to join channel (not using registered nickname)"*, which is expected.
4. <span id="irc-step-4" class="step-anchor">**Register your nickname.**</span> Because of bot attacks, you must stay connected for **30 minutes** first. Then type:

   ```
   /msg NickServ REGISTER yourpassword youremail@example.com
   ```

   If you get a confirmation e-mail, follow it.
5. <span id="irc-step-5" class="step-anchor">**Join the channel:**</span>

   ```
   /join #exodus-home
   ```

From then on, log in each time you connect with `/msg NickServ IDENTIFY yourpassword`, or put the password in your client's *NickServ password* (or *SASL*) field so it happens automatically.

# Working on the site

Every push to `main` builds and deploys the site automatically (see
`.github/workflows/deploy.yml`).

## Running it locally

### Requirements

- [Ruby](https://jekyllrb.com/docs/installation/) 3.3 (what the deploy workflow uses, so the safest to match).
  - Windows: install **Ruby+Devkit 3.3** from <https://rubyinstaller.org/> and let it run `ridk install` at the end.
  - Linux / macOS: use your package manager or a version manager such as `rbenv`.
- Bundler: `gem install bundler`

### With the test script

- **Windows**: double-click `serve.bat` in the `tools` folder, or open a command prompt in `tools` and run `serve`.
- **Linux / macOS**: from the `tools` folder run `./serve.sh`.

The script installs the gems if needed, stops any old server still on port 4000, then builds and serves the site.
Open <http://localhost:4000>.

- **Saving any file** (pages, layouts, `_data/`, CSS, images) rebuilds the whole site and the browser reloads by itself.
  The site is small, so a full rebuild takes about a second; Jekyll's cache (`.jekyll-cache`) keeps Markdown and styles that did not change.
- **Changing `_config.yml`** restarts the server by itself (`tools/serve.rb` watches it), because Jekyll only reads that file when it starts.

| Option  | What it does |
| :------ | :----------- |
| *(none)* / `build` | Builds and serves the site. |
| `clean` | Deletes the previous build and cache first. Only needed if something still looks wrong. |

Set `JEKYLL_HOST=0.0.0.0` before running to open the site from other devices on your network,
or `JEKYLL_PORT` to use a port other than 4000.

### Manually

From the root of the repository:

```bash
bundle install
bundle exec jekyll serve --livereload
```

Then open <http://localhost:4000>.

> Run this way, changes to `_config.yml` are not picked up while the server runs - stop it (Ctrl+C) and start it again. The test script does that for you.

## Editing the site

### Server address, links and the Message Of The Day

Everything here lives in `_config.yml`:

| Setting | What it changes |
| :------ | :-------------- |
| `server.address` | The address shown on the page, and the one the live status looks for. |
| `server.join_url` | The **Join Server** buttons, in the header and the live status box (`renegade://<address>`). |
| `server.location` | "Hosted in ..." |
| `server.status_url` | Where the live status comes from (CnCNet's public server list). Remove the line to hide the live status box (the header keeps its Join Server button). |
| `discord_url`, `steam_url` | The Discord and Steam buttons in the header. Remove one to hide its button. |
| `connect_help` | The "Not sure how to connect?" links. Add or remove `- name:` / `url:` pairs. |

The Message Of The Day text itself (the Renz0r.net line) is in `index.html`, in the `motd-text` paragraph.

### Adding, removing or reordering a map

Edit `_data/maps.yml`. Each map is two or three lines, in the order the server plays them:

```yaml
- name: M05                              # the map's file name, exactly as !rotation shows it
  description: "Mission 6: Deadly Reunion" # campaign name and/or a note
  image_credit: vgmaps                   # optional: who made the preview image (see below)
```

Put the description in quotes if it contains a colon (`:`). The README's own map table is written by hand, so update it too.

### Adding a map preview image

1. Name the image exactly like the map's `name` in `_data/maps.yml`, keeping the same capitals: `M05.webp`, `Coop_Tropics_B1.png`.
   `.webp`, `.png`, `.jpg` and `.jpeg` all work; `.webp` keeps the files small.
2. Put it in `assets/images/maps/`.
3. That's it: the map's row in the table gets the picture icon, and clicking the row opens the preview. Any size or shape works; the preview box fits the largest image.
4. If someone else made the image, credit them: add `image_credit: <key>` to the map in `_data/maps.yml`, using a key from `_data/credits.yml`.
   To add a new source there:

   ```yaml
   vgmaps:                       # the key used by image_credit
     name: vgmaps.de             # shown as "Credit to vgmaps.de"
     url: https://vgmaps.de/maps/pc/command-and-conquer-renegade
   ```

5. In this README, turn the map's name into a link to the image, like the others: `[M05](assets/images/maps/M05.webp)`.

Images downloaded from vgmaps.de come with long names such as
`command-and-conquer-renegade-mission-06-deadly-reunion-in-game-map-pc-map.webp`; rename them to the map name first.
The campaign file numbers are one behind the mission numbers: Mission 1 is `M13`, Mission 2 is `M01`, ..., Mission 12 is `M11`,
and the tutorial is `M00_Tutorial`.

### Map pictures from RenegadeViewer

Most map pictures come from RenegadeViewer's **Save PNG** export: a folder named `<date>-<map file>`
(e.g. `06_11_2026_03_12_49-C&C_Coop_B02_B10`) with `World/`, `Empty/`, `Filled/`, `Floors/` and `layers.txt`.
Put the export folder in the repository's root (export folders are in `.gitignore`), then run:

```bash
python tools/convert_maps.py "06_11_2026_03_12_49-C&C_Coop_B02_B10"
python tools/convert_maps.py "06_11_2026_*"        # a pattern converts several
```

It writes the normal picture (`assets/images/maps/<map>.webp`, 1600 px), the high-detail one (`hd/`, 9104 px) and the
layering pictures in both sizes (`layers/<map>/` and `layers/<map>/hd/`), all cut to the same box so they line up.
The full-size layers take a few minutes per map; to make only those, for maps converted already, run
`python tools/convert_maps.py --hd-layers [--budget SECONDS] <export folders>` (it skips files that exist, so it can be
stopped and run again). "C&C_" is left off the name. A map with no
units has no `World/`; the script then uses `Empty/` (e.g. `Empty/all_ttm1_92BB640B.png`), which is the same picture.
Needs Python 3 and Pillow (`pip install pillow`); a 16384 px export takes about a minute and 1 GB of memory.
Add `image_credit: renegadeviewer` to the map in `_data/maps.yml`.

### The map preview

Opened by clicking a map's row. ❮ ❯ or the ← → keys step through every map that has an image;
the mouse wheel, pinching or + / − zoom, dragging moves the map, double-click zooms in or out, and `0` or Reset goes back to 100%.
The zoom carries over from map to map. When a map is the one being played, it shows the same **Now playing** badge as the table.

### Map preview views

The buttons under the map switch between the map image, the in-game photo and the game's loading screen (only the ones
the map has). The loading screen is the picture from `assets/images/loadscreens/` with the game's own text drawn on
top, from `_data/loadscreens.yml` (positions on the game's 640x480 grid).

**Details: Low / High** (maps with a picture in `hd/`): Low, the default, is the normal picture; High downloads the big
one (with a progress bar) so the details stay readable when zoomed in. Both zoom up to 1000% and keep the zoom when you
switch, so seeing the blurry version is the viewer's choice. The choice is remembered per browser.

**Try out layering system?** (off by default): shows the map in parts you can switch on and off (Map, Units and
objects, Editor) or one floor at a time. It follows Details: Low uses the 1600 px layer pictures, High the full-size ones
in `layers/<map>/hd/`.

Under the map, the left card has the map's **Weapons** (Starting / Map / Secrets tabs; everyone starts with the Pistol and
Timed C4), the **Purchase terminal** (folded; Characters and Vehicles open their pages, hover a card for details) and the
**Buildings** on the map. The objectives are on the right.

### Purchase terminal

Each map's preview shows the first page of the purchase terminal for its side (GDI or Nod cards from `assets/images/hud/`),
with what isn't sold there greyed out. It comes from `terminal:` in `_data/map_marks.yml` (set in the Map marker's **Map info**): `full`, `no-vehicles`,
`vehicles-destroyed` (a stock map whose vehicle building starts destroyed, so the game shows "Destroyed") or `none`
(no terminal at all). Maps without it don't show the terminal; the debug panel lists them. Beacons are greyed out on
every map while `server.beacons_for_sale` in `_config.yml` is `false`.

### Map marks and map info

Spots on a map's overhead image: **objectives**, **spawn points**, **secrets**, **vehicles**, **pickups**, **teleports**,
**other**, **notes** (small dots), **lines** (walls: solid white = visible, dashed red = invisible) and **arrows**. An objective mark can show the game's own objective picture; any other mark can show
a HUD icon instead of its symbol (a pickup such as a keycard, health or the Data Disc, or the GDI / Nod logo). Marks can say
which **floor** they're on, and secrets, vehicles, pickups and other can say **how many** there are (none = infinite, shown
as ×N otherwise). A mark can **lead to** others (an objective that gives a keycard), drawn as a dash-dot line. Marks on the
same spot fan out so each can be seen.

In the map preview, hovering a mark shows its name, amount, floor, what it leads to, note and first picture; clicking it
keeps the card open and steps through all its pictures. The chips under the map switch a kind on or off, and a **Floor**
list (also set by the layering floor) shows one floor's marks. Rows with marks get a pin icon in the table.

To change marks or a map's game info, open the **Map marker** tool (Index > Tools, or `/tools/map-marker/`):

1. Pick the map. It has the same zoom, **Details: Low / High** and layering controls as the map preview (scroll or pinch
   to zoom, drag the map to move it, + / − / 0).
2. **Mode: Place** - pick a kind; the **Placing** box shows what it can be (Pickup shows the pickups, Objective the
   objective pictures, the rest the GDI / Nod logos, or the plain symbol). Click the map to add one; for an **Arrow** or a
   **Line**, drag from one end to the other. A **Teleport** takes two clicks, the entrance then the exit, and links them. **Mode: Select** - clicks only pick marks, so nothing is added by accident.
3. Drag a mark to move it (an arrow's two dots move its ends); click it to change its kind, floor, amount, picture or icon,
   links (**Link to a mark…**, then click the mark it leads to), name, note and pictures. Arrow keys nudge it, Delete
   removes it, a click outside the map clears the selection. Drag marks in the list to reorder them: the top of the list is
   drawn on top.
4. **Map info** under the map: the **Objectives** (one step per line; objective marks are suggested), **Weapons** (Starting,
   On the map, Secrets; weapon pickups and secrets with a weapon icon are suggested), the **Purchase terminal** and the
   **Buildings** (with counts, and which side the players are on).
5. Your work is kept in that browser until the site has it, so you can close the page and come back.
6. Copy the text at the bottom (or download it) over the whole of `_data/map_marks.yml`, put the pictures you added in
   `assets/images/marks/` with the same names, and commit.

The file format is described at the top of `_data/map_marks.yml`; it can also be edited by hand.

### Sounds

The **Sounds** section has two parts: **In-game commands** (the `!sounds` list, from `_data/sounds.yml`; shown as
"Coming soon" while it's empty) and **In-game sounds**: all 10,299 sounds of the game and the co-op maps, with search,
categories (also linked from the Index, e.g. `#sounds-eva`), sorting, a waveform and the line spoken with who says it.
The sounds load only when the section is opened.

To rebuild them from a RenegadeViewer sound export and its spreadsheet:

```bash
python tools/convert_sounds.py Sounds/renegade_sounds_10299 Renegade_Sounds.xlsx
```

It converts each sound to a small `.m4a` (skipping ones already done) and writes `assets/sounds/index.json` and
`_data/sound_categories.yml`. Needs Python 3, openpyxl and ffmpeg. The raw export and spreadsheet stay out of git.

### Debug mode

The **Debug mode** switch at the bottom of every page (or `?debug=1` / `?debug=0` in the address, which is also remembered)
makes the map table show every icon, with the missing ones in red, and adds a **Debug panel** at the bottom of the home page:
a checklist of which maps have weapons, a map image, an in-game photo, marks, objectives and a faction. Hover a red cross to
see which file or field it needs.

### Live server status

The **Message Of The Day** box shows whether the server is online, the current map (with its mission name and preview),
players, time left and who's playing, with **Join Server** next to the status. The visitor's browser reads it from CnCNet's
public server list (`server.status_url` in `_config.yml`) when the page opens and then every minute, and the map being played
gets a **Now playing** badge in the rotation table.

It asks the server itself first (`status.json`, written every ~5 minutes by the "Server status" workflow) and only uses
CnCNet when that check is out of date or the server didn't answer it. On Nod maps the box explains why the count can be 0,
with a folded **Technical note** about the BRenBot version; keep `server.brenbot` in `_config.yml` up to date, and remove it
once the server runs BRenBot 1.54.4 or newer.

CnCNet's own list only updates every so often, so the page says when it last checked rather than offering a refresh button.
That address isn't documented by CnCNet, so it could change: if the live box ever shows "Couldn't reach the server list",
open <https://cncnet.org/renegade> and check where its server list comes from now.

### Adding a section to the home page

1. In `index.html`, copy one of the `<details class="panel" id="...">` blocks (Map rotation or IRC) and give it a new `id` and title.
   Add `open` to `<details ...>` to have it start expanded.
2. Add it to the Index box (the `toc-menu` list in `index.html`): copy an `<li>`, update the number, the `href="#your-id"`, the title and the one-line description.
3. Add it to `sections:` at the top of `index.html` to give it a quick link in the header that follows the page:

   ```yaml
   sections:
     - title: Map rotation
       id: map-rotation
     - title: Your section
       id: your-id
   ```

To write the section in Markdown, put it in `_includes/your-section.md` and render it the way the IRC section does
(`{% capture %}{% include ... %}{% endcapture %}` and `| markdownify`).
To link to a specific step or paragraph, give it an id with `<span id="...">...</span>` and link to `#...` - the IRC steps (`#irc-step-4`) work this way.

### Themes

The site is dark by default, styled after Renegade's menus and loading screens (red and black, yellow titles, orange-outlined buttons),
with a light theme behind the sun/moon button in the header. The choice is remembered in the browser.
The GDI / Nod button next to it switches the site's colours between GDI gold (default) and Nod red.
Adding `?theme=` to a URL sets (and remembers) both: `light` or `dark`, and `gdi` or `nod`, for example
<https://cnc-exoduscommunity.github.io/?theme=light,nod>.
To change colours, edit the variables at the top of `assets/css/style.css` (one block per theme).

### Footer revision line

"Site Revision" in the footer fills itself in from the last git commit when the site is built - nothing to update by hand.

### Adding a page

Create a `.md` file with a front matter block at the top:

```markdown
---
title: My page
---

# My page

Content here.
```

`my-page.md` is served at `/my-page.html`; add `permalink: /my-page/` to the front matter for a cleaner URL.

## Deployment

One-time setup on GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

It has to be **GitHub Actions**, not "Deploy from a branch": the site uses Jekyll 4 and its own plugin (`_plugins/last_commit.rb`,
for the footer's revision line), and GitHub's branch builds support neither. The workflow that does the build is
`.github/workflows/deploy.yml`.

After that, push to `main` and the **Deploy to GitHub Pages** workflow builds the site and publishes it.
It can also be run by hand from the **Actions** tab.
